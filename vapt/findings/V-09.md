## Affected

- **Endpoint:** `GET /api/drivers/{id}/trips` ([`DriverController.trips()`](../../app/src/main/java/co/fleetsec/vapp/web/DriverController.java))
- Devuelve `tripRepo.findByDriverId(id)` sin comprobar que el solicitante sea el dueño ni admin.

## Description

El endpoint recibe `id` por path y devuelve los viajes de ese conductor sin verificación de ownership. Cambiar el `id` expone los viajes (origen, destino, horarios) de **otros** conductores.

## CVSSv3.1 — justificación métrica por métrica

`CVSS:3.1/AV:N/AC:L/PR:N/UI:N/S:U/C:L/I:N/A:N` → **5.3 (Medium)**

| Métrica | Valor | Justificación (demostrada) |
|---|---|---|
| **AV/AC/PR/UI** | N/L/N/N | Endpoint HTTP GET, sin auth (V-11), incremental de `id`. |
| **S** | **U** | Dentro de la app. |
| **C** | **L** | **Demostrado:** acceso a los viajes (datos de movimiento) de otro conductor. Alcance acotado a los datos de `trips`, no PII directa completa. |
| **I** | **N** | Solo lectura. |
| **A** | **N** | Sin impacto de disponibilidad. |

> **Distinción con V-11:** V-11 es la ausencia de **autenticación** (nadie prueba identidad). V-09 es la ausencia de **autorización/ownership**: aunque se añadiera autenticación, un usuario autenticado podría seguir leyendo los viajes de otro cambiando el `id`. Son controles distintos; V-09 persiste tras remediar V-11.

## PoC

```bash
curl -s "http://localhost:8080/api/drivers/2/trips"
# → [{"id":1,"driverId":2,"origin":"Bogotá - Terminal","destination":"Chía - CC Fontanar","startedAt":"2026-06-14T08:15:00Z"}]
#   viajes del conductor 2, accedidos sin ser el dueño (iterar id = enumerar todos)
```

### Evidencia adicional del pipeline (doble fuente)

- **SAST (Semgrep):** custom rule `fleetsec-missing-authz-on-pathvariable-endpoint` (WARNING) en `DriverController.java:111` (`@GetMapping` con `@PathVariable` sin `@PreAuthorize`).

> **Nota post-remediación (FP documentado):** igual que en [V-05](V-05.md), la authz de ownership es por **check explícito** (`if (!user.isAdmin() && !id.equals(user.driverId()))`), no `@PreAuthorize`. La custom rule **sigue marcando el WARNING** — **falso positivo conocido**, no bloqueante. La remediación está **validada por test dual** (`EnforcementRemediationTest.v09_otherDriverTrips_isForbidden` → 403 / `v09_ownTrips_isOk` → 200), no por la ausencia del WARNING. Ver [`pipeline/README.md` § Falsos positivos conocidos](../../pipeline/README.md).

## Impact

- **Confidencialidad (Baja/Media):** enumeración de los viajes de todos los conductores → **datos de geolocalización/movimiento**, sensibles bajo Ley 1581. Iterando `id` se reconstruyen patrones de desplazamiento de la flota.
- **Interacción:** combinado con V-11 (sin auth), la exposición es totalmente anónima.

## Remediation

Verificar ownership contra el sujeto autenticado:

```java
@GetMapping("/{id}/trips")
@PreAuthorize("#id == principal.driverId or hasRole('ADMIN')")
public ResponseEntity<?> trips(@PathVariable Long id, @AuthenticationPrincipal ...) { ... }
```
O filtrar por el `id` del SecurityContext, ignorando el `id` del path para usuarios no-admin.

**Test dual (implementado · commit `49c2153`):**
1. **Rechazo:** `EnforcementRemediationTest.v09_otherDriverTrips_isForbidden` — el conductor A pidiendo los viajes de B → `403` (autenticado pero no autorizado, no 401).
2. **Flujo legítimo OK:** `EnforcementRemediationTest.v09_ownTrips_isOk` — un conductor pidiendo sus propios viajes → `200`.
