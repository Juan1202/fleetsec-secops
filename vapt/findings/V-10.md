| Campo | Valor |
|---|---|
| **ID** | V-10 |
| **Título** | Secreto de firma JWT y credenciales de admin hardcoded en configuración (repo público) |
| **Severidad** | 🟠 **HIGH** |
| **CVSSv3.1** | **7.5** |

| **CWE** | [CWE-798](https://cwe.mitre.org/data/definitions/798.html) · Use of Hard-coded Credentials |

## Affected

- **Componente:** [`app/src/main/resources/application.yml:41`](../../app/src/main/resources/application.yml#L41) (`app.jwt.secret`) y [`:45`](../../app/src/main/resources/application.yml#L45) (`app.admin.password`)
- **Consumidores:** `JwtService(@Value("${app.jwt.secret}"))` · `AuthController(@Value("${app.admin.password}"))`
- **Agravante:** el repositorio es **público** (ADR-002) → cualquiera con acceso al source lee los secretos.

## Description

El secreto de firma HS256 de los JWT y la contraseña de administrador están **hardcoded en texto plano** en `application.yml`, versionados en un repo público:

```yaml
# application.yml:40-45
app:
  jwt:
    secret: "S3cr3tK3y-FleetSec-2026-Pr0d-DoNotShare-9f83b1c0a7e24d56"   # línea 41
  admin:
    username: "admin"
    password: "FleetS3c@dm1n-2026!"                                       # línea 45
```

No es la definición genérica de CWE-798: son estos dos valores literales, consumidos por `JwtService` (firma de tokens) y `AuthController` (login de admin). Con el secret, un atacante forja tokens HS256 válidos para **cualquier** identidad; con la contraseña, se autentica como admin directamente.

## CVSSv3.1 — justificación métrica por métrica

`CVSS:3.1/AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:N/A:N` → **7.5 (High)**

> Criterio: se puntúa lo demostrado. La **exposición del secreto** es C:H real e independiente del enforcement.

| Métrica | Valor | Justificación (demostrada) |
|---|---|---|
| **AV** | **N** | El secreto se lee del repo público (red); las credenciales se usan contra el endpoint HTTP de login. |
| **AC** | **L** | Leer un archivo del repo y usar la credencial: trivial, reproducible. |
| **PR** | **N** | El repo es público; no se requiere ningún privilegio para leer los secretos. |
| **UI** | **N** | Sin interacción de otra víctima. |
| **S** | **U** | Los secretos operan dentro de la authority de la app. |
| **C** | **H** | **Demostrado:** el JWT secret y la contraseña de admin son datos confidenciales expuestos; con el secret se forjan tokens de cualquier identidad (`valid:true, sub:attacker, role:ADMIN`). |
| **I** | **N** | **Demostrado ausente:** poseer las credenciales no habilita escritura gateada en esta app — ningún endpoint enforcea el token (ver [V-11](V-11.md)). |
| **A** | **N** | Sin impacto de disponibilidad. |

**Test 1 — login con la contraseña hardcoded → token de ADMIN:**
```bash
curl -s -X POST http://localhost:8080/api/auth/login -H "Content-Type: application/json" \
  -d '{"username":"admin","password":"FleetS3c@dm1n-2026!"}'
# → {"role":"ADMIN","token":"eyJhbGciOiJIUzI1NiI...."}
```

**Test 2 — forja de token para una identidad arbitraria usando el secret hardcoded:**
```python
# HMAC-SHA256 con el secret de application.yml, payload sub=attacker role=ADMIN
secret = 'S3cr3tK3y-FleetSec-2026-Pr0d-DoNotShare-9f83b1c0a7e24d56'
# ... firma HS256 ...
```
```bash
curl -s -X POST http://localhost:8080/api/auth/validate -H "Content-Type: application/json" \
  -d '{"token":"<TOKEN_FORJADO>"}'
# → {"role":"ADMIN","sub":"attacker","valid":true}   ← token forjado ACEPTADO
```

### Evidencia adicional del pipeline (doble fuente)

- **SAST (Semgrep):** custom rule `fleetsec-hardcoded-secret-in-yaml` (ERROR) en `application.yml:41` y `:45`. SARIF en Code Scanning.
- **Nota de cobertura:** **gitleaks NO detecta este secreto** — sus reglas detectan por firma/entropía, no secretos semánticos de config (`app.jwt.secret: <literal legible>`). Es la razón por la que existe la custom Semgrep rule (documentado en el pipeline). Doble fuente = SAST manual + PoC, no gitleaks.

## Impact

- **Confidencialidad (Alta) — demostrada:** exposición del secreto de firma y de las credenciales de admin en un repo público; forja de tokens de cualquier identidad.
- **Integridad / Disponibilidad — no demostradas:** ningún endpoint enforcea el token (ver [V-11](V-11.md)).
- **⏰ Bomba de tiempo (interacción con V-11):** si se remedia V-11 (se activa enforcement de auth) **sin** rotar estos secretos, el secret expuesto se vuelve el vector directo de **account takeover total** (forja de admin → C:H/I:H). **Orden de remediación:** rotar/migrar los secretos (este finding) **antes o junto con** activar el enforcement.
- **Ley 1581:** las credenciales dan acceso a la PII de conductores; su exposición es un incidente de seguridad reportable.

## Remediation

Migrar los secretos a **variables de entorno / gestor de secretos** — nunca a otro archivo del repo (requisito explícito del brief para V-10):

```yaml
# application.yml — referencia por env, sin valor literal
app:
  jwt:
    secret: ${APP_JWT_SECRET}
  admin:
    password: ${APP_ADMIN_PASSWORD}
```

- Inyectar `APP_JWT_SECRET` / `APP_ADMIN_PASSWORD` vía entorno del contenedor o AWS Secrets Manager (Sprint 3).
- **Rotar** el secreto y la contraseña expuestos (ya comprometidos por estar en el historial público).
- Validar en el arranque que las variables estén presentes (fail-fast).

**Test dual (FSEC-17):**
1. **Rechazo:** con el secret viejo, un token forjado ya NO valida (secret rotado).
2. **Flujo legítimo OK:** el login y la firma funcionan con el secret provisto por entorno.
