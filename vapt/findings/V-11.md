# V-11 · Missing Authentication Enforcement (todos los endpoints)

| Campo | Valor |
|---|---|
| **ID** | V-11 _(hallazgo adicional — bonus)_ |
| **Título** | Ningún endpoint valida autenticación: acceso sin credenciales a funciones sensibles |
| **Severidad** | 🟠 **HIGH** |
| **CVSSv3.1** | **8.2** |
| **Vector** | `CVSS:3.1/AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:L/A:N` |
| **CWE** | [CWE-306](https://cwe.mitre.org/data/definitions/306.html) · Missing Authentication for Critical Function |
| **OWASP Top 10 2021** | [A01:2021 – Broken Access Control](https://owasp.org/Top10/A01_2021-Broken_Access_Control/) |
| **OWASP ASVS 4.0.3** | V4.1.1 (enforcement de control de acceso en cada request), V1.4.1 |
| **Estado** | **Open** _(se actualiza a Fixed en FSEC-17)_ |

---

## Affected

- **Componente:** toda la app — **no existe** `SecurityFilterChain`, `@PreAuthorize`, `@Secured` ni la dependencia `spring-boot-starter-security` (verificado por grep sobre `app/src/` y `app/pom.xml`).
- **Endpoints sensibles expuestos sin auth:** `/api/drivers/search` (PII), `/api/drivers/{id}` PATCH, `/api/drivers/{id}/trips`, `/api/reports/download`, `/api/vehicles/{id}/webhook`, `/api/vehicles/import`.

## Description

La app **emite** tokens JWT (`/api/auth/login`) pero **no los exige ni valida en ningún endpoint**: no hay filtro de seguridad ni anotaciones de autorización. Todos los endpoints, incluidos los que exponen PII o mutan datos, responden a peticiones **anónimas**. Este es el hallazgo **raíz** que acota (hoy) el impacto directo de [V-02](V-02.md) y [V-10](V-10.md): el mecanismo de auth existe pero es decorativo.

## PoC

Todas las peticiones se ejecutan **sin header `Authorization`** y obtienen `200 OK`:

```bash
# PII de conductores, anónimo:
curl -s "http://localhost:8080/api/drivers/search?q=Ana"           # → datos con cédula/email/teléfono
# Viajes de otro conductor, anónimo (ver también V-09 IDOR):
curl -s "http://localhost:8080/api/drivers/2/trips"                # → viajes del driver 2
# Modificación de datos, anónimo (ver también V-05 mass assignment):
curl -s -X PATCH "http://localhost:8080/api/drivers/2" -H "Content-Type: application/json" -d '{"phone":"+57 3000000000"}'
# Descarga de archivos, anónimo (ver también V-06 path traversal):
curl -s "http://localhost:8080/api/reports/download?file=reporte-flota-2026-06.txt"
```

Ninguna exige token. El `POST /api/auth/login` emite JWTs que **no se usan** como control de acceso.

### Cobertura del scanner

- **SAST (Semgrep):** la custom rule `fleetsec-missing-authz-on-pathvariable-endpoint` (WARNING) marca los endpoints con `@PathVariable` sin `@PreAuthorize` (`DriverController` PATCH/trips) — señal parcial de este problema.
- La **ausencia global** de un filtro de seguridad es un hallazgo de arquitectura que se confirma mejor por revisión manual (grep de `SecurityFilterChain`/dependencia security → 0 resultados).

## Impact

- **Confidencialidad (Alta) — demostrada:** exposición anónima de PII de ~60.000 conductores en producción (**Ley 1581**: acceso no autorizado a datos personales, incidente reportable a la SIC).
- **Integridad (Baja) — demostrada:** modificación de datos sin autenticación.
- **Finding raíz / interacción:** hoy V-11 **acota** el impacto directo de [V-02](V-02.md) y [V-10](V-10.md) (los tokens no gatean nada). Pero la remediación de V-11 (activar enforcement) **invierte** la relación: sin arreglar V-02/V-10 primero, el enforcement se apoyaría en un mecanismo de auth roto → account takeover.
- **Orden de remediación (reporte Sprint 2):** (1) arreglar V-02 (JWT) + V-10 (secrets), (2) recién entonces activar enforcement (V-11). Nunca V-11 solo.

## Remediation

Incorporar Spring Security con enforcement por defecto y autorización por endpoint:

```java
@Bean
SecurityFilterChain filterChain(HttpSecurity http) throws Exception {
    http.authorizeHttpRequests(auth -> auth
            .requestMatchers("/api/auth/login").permitAll()
            .anyRequest().authenticated())          // todo lo demás exige auth
        .oauth2ResourceServer(o -> o.jwt(Customizer.withDefaults()));  // valida firma (ver V-02)
    return http.build();
}
```

Complementar con verificación de ownership por recurso (`@PreAuthorize` con `#id == principal.id or hasRole('ADMIN')`) para cerrar también V-05/V-09.

**Test dual (FSEC-17):**
1. **Rechazo:** una petición sin token a `/api/drivers/search` devuelve `401`.
2. **Flujo legítimo OK:** con un token válido (firmado, tras remediar V-02), la petición se autoriza.
