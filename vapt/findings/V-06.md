## Affected

- **Endpoint:** `GET /api/reports/download?file=`
- **Componente:** [`ReportController.download()`](../../app/src/main/java/co/fleetsec/vapp/web/ReportController.java#L44) — `new File(baseDir, file)` sin normalizar ni verificar contención.

## Description

El parámetro `file` se concatena al directorio base sin `Path.normalize()` ni verificación de que el resultado quede dentro de `baseDir`:

```java
File target = new File(baseDir, file);         // file = "../../../etc/passwd" escapa el directorio
byte[] content = Files.readAllBytes(target.toPath());
return ResponseEntity.ok()... .body(content);
```

Secuencias `../` permiten leer cualquier archivo legible por el proceso.

## CVSSv3.1 — justificación métrica por métrica

`CVSS:3.1/AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:N/A:N` → **7.5 (High)**

| Métrica | Valor | Justificación (demostrada) |
|---|---|---|
| **AV/AC/PR/UI** | N/L/N/N | Endpoint HTTP GET, sin auth (V-11), sin interacción. |
| **S** | **U** | Lectura con los privilegios del proceso. |
| **C** | **H** | **Demostrado:** lectura de `/etc/passwd` (`root:x:0:0:...`) fuera del directorio de reportes. |
| **I** | **N** | Solo lectura. |
| **A** | **N** | Sin impacto de disponibilidad. |

## PoC

```bash
curl -s "http://localhost:8080/api/reports/download?file=../../../../../../etc/passwd"
# → root:x:0:0:root:/root:/bin/sh
#   bin:x:1:1:bin:/bin:/sbin/nologin
#   ...   ← /etc/passwd leído (fuera de app/reports)
```
**Contraste legítimo:** `file=reporte-flota-2026-06.txt` devuelve el reporte válido dentro del directorio.

### Evidencia adicional del pipeline (doble fuente)

- **SAST (Semgrep):** `tainted-file-path` (ERROR) en `ReportController.java:44`. SARIF en Code Scanning.

## Impact

- **Confidencialidad (Alta):** lectura de archivos del contenedor — config, secrets (p. ej. `application.yml` con V-10), `/etc/passwd`.
- **Ley 1581:** si se leen archivos con PII o backups, exposición de datos personales.

## Remediation

Normalizar y verificar contención en el directorio base:

```java
Path base = Paths.get(baseDir).toAbsolutePath().normalize();
Path target = base.resolve(file).normalize();
if (!target.startsWith(base)) {
    return ResponseEntity.status(HttpStatus.FORBIDDEN).build();  // escapa el directorio
}
```
Alternativa robusta: allowlist de nombres de archivo / IDs indirectos (no exponer el path).

**Test dual (implementado · commit `cc99ce5`):**
1. **Rechazo:** `InputValidationRemediationTest.v06_pathTraversal_isRejected` — `file=../../../../etc/passwd` → `400`, sin leer fuera del base (la ruta normalizada no queda contenida).
2. **Flujo legítimo OK:** `v06_legitimateReport_isDownloaded` — `file=reporte-flota-2026-06.txt` → `200` con el reporte.
