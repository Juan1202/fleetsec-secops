# V-07 · Missing Rate Limiting en `POST /api/auth/login`

| Campo | Valor |
|---|---|
| **ID** | V-07 |
| **Título** | Endpoint de login sin throttling ni lockout: fuerza bruta / credential stuffing |
| **Severidad** | 🟡 **MEDIUM** |
| **CVSSv3.1** | **5.3** |
| **Vector** | `CVSS:3.1/AV:N/AC:L/PR:N/UI:N/S:U/C:L/I:N/A:N` |
| **CWE** | [CWE-307](https://cwe.mitre.org/data/definitions/307.html) · Improper Restriction of Excessive Authentication Attempts |
| **OWASP Top 10 2021** | [A07:2021 – Identification and Authentication Failures](https://owasp.org/Top10/A07_2021-Identification_and_Authentication_Failures/) |

## Affected

- **Endpoint:** `POST /api/auth/login` ([`AuthController.login()`](../../app/src/main/java/co/fleetsec/vapp/web/AuthController.java#L52))
- No hay throttling, backoff, lockout ni CAPTCHA por intentos fallidos.

## Description

`login()` valida credenciales y devuelve `401` en caso de fallo, pero **no limita** la cantidad de intentos. Un atacante puede iterar contraseñas sin restricción (fuerza bruta / credential stuffing).

## CVSSv3.1 — justificación métrica por métrica

`CVSS:3.1/AV:N/AC:L/PR:N/UI:N/S:U/C:L/I:N/A:N` → **5.3 (Medium)**

| Métrica | Valor | Justificación (demostrada) |
|---|---|---|
| **AV/AC/PR/UI** | N/L/N/N | Endpoint HTTP, automatizable, sin credenciales previas. |
| **S** | **U** | Dentro de la app. |
| **C** | **L** | Impacto **indirecto**: habilita adivinar credenciales; el compromiso final depende de la fortaleza de las contraseñas. No hay fuga directa por este vector. |
| **I** | **N** | No hay modificación por el vector en sí. |
| **A** | **N** | No se demostró DoS. |

> Se puntúa el **impacto directo** (facilitar fuerza bruta = C:L), no el resultado hipotético de un login exitoso. El control ausente es real; su explotación end-to-end depende de otros factores.

## PoC

```bash
for i in $(seq 1 15); do
  curl -s -o /dev/null -w "%{http_code} " -X POST http://localhost:8080/api/auth/login \
    -H "Content-Type: application/json" -d '{"username":"admin","password":"x'$i'"}'
done
# → 401 401 401 401 401 401 401 401 401 401 401 401 401 401 401
#   15 intentos fallidos consecutivos, NINGÚN 429 ni lockout → sin rate limiting
```

### Por qué el scanner NO lo caza

- Ni SAST ni DAST tienen una prueba por defecto de "ausencia de rate limiting"; es un control negativo que requiere el script de fuerza bruta manual mostrado arriba.

## Impact

- **Confidencialidad (indirecta):** habilita fuerza bruta / credential stuffing contra `/login`.
- **Interacción (agravante):** combinado con **V-10** (contraseñas débiles/conocidas, `admin123`, `Bogota2026`) el ataque es altamente efectivo — sin lockout, adivinar `admin123` es cuestión de segundos. Y con **V-02/V-11** el valor de una sesión válida cambia según el enforcement.

## Remediation

- **Rate limiting** por IP y por cuenta en `/auth/*` (p. ej. Bucket4j, o el rate-limit del WAF — 1.000 req/5min del Entregable 03).
- **Lockout progresivo / backoff** tras N fallos; CAPTCHA o MFA como defensa adicional.
- Respuestas de tiempo constante para no filtrar validez de usuario.

**Test dual (FSEC-17):**
1. **Rechazo:** tras N intentos fallidos, el endpoint responde `429` (o bloquea temporalmente).
2. **Flujo legítimo OK:** un login válido dentro del umbral responde `200`.
