| Campo | Valor |
|---|---|
| **ID** | V-05 |
| **Título** | Actualización parcial vincula el body completo sobre la entidad: modificación arbitraria de campos + fuga de password |
| **Severidad** | 🟠 **HIGH** |
| **CVSSv3.1** | **8.1** |

## Affected

- **Endpoint:** `PATCH /api/drivers/{id}` ([`DriverController.java:82-83`](../../app/src/main/java/co/fleetsec/vapp/web/DriverController.java#L82-L83))
- **Sink:** `ObjectMapper.updateValue(driver, updates)` — mergea **todas** las claves del body sobre la entidad persistida.

## Description

El endpoint vincula el body JSON completo sobre la entidad `Driver` sin allowlist de campos:

```java
Driver merged = mapper.updateValue(driver, updates);   // updates = body del atacante, TODAS las claves
Driver saved = drivers.save(merged);
return ResponseEntity.ok(saved);                        // devuelve la entidad, incluido password
```

Un atacante inyecta campos sensibles (`role`, `password`, cualquier columna) que no debería poder editar. Además, la respuesta serializa la entidad completa, **filtrando el `password`**.

## CVSSv3.1 — justificación métrica por métrica

`CVSS:3.1/AV:N/AC:L/PR:N/UI:N/S:U/C:L/I:H/A:N` → **8.1 (High)**

| Métrica | Valor | Justificación (demostrada) |
|---|---|---|
| **AV/AC/PR/UI** | N/L/N/N | Endpoint HTTP, trivial, sin auth (V-11), sin interacción. |
| **S** | **U** | Modifica registros dentro de la app. |
| **C** | **L** | **Demostrado:** la respuesta filtra el `password` del conductor (`Bogota2026`). |
| **I** | **H** | **Demostrado — escritura NO autorizada y PERSISTENTE de campos sensibles.** El `I:H` viene de la **integridad de los DATOS**, no de "obtener privilegios admin": un PATCH modifica `phone`, `email`, `role` (y cualquier columna) de cualquier conductor, y el cambio **persiste en la BD** (verificado re-leyendo en otra request). Es corrupción de datos personales, independiente de que algo consuma el `role`. |
| **A** | **N** | Sin impacto de disponibilidad. |

> **Por qué I:H (y no un impacto de auth como V-02):** el vector demostrado es la **escritura persistente de campos prohibidos** (dato modificado y guardado), no la obtención de una identidad admin. La escalada de rol como *privilegio* estaría acotada por V-11 (nada enforcea el rol) — igual que V-02, que por eso es MEDIUM. Pero la **modificación de datos** no depende de ningún enforcement: el registro queda corrupto en la base. Ejes separados, sin circularidad.

## PoC

```bash
# 1) estado inicial (id=2): phone=+57 3109988776, role=DRIVER
# 2) PATCH de campos prohibidos:
curl -s -X PATCH http://localhost:8080/api/drivers/2 -H "Content-Type: application/json" \
  -d '{"phone":"+57 9999999999","role":"ADMIN","email":"pwned@evil.com"}'
# → {"id":2,"password":"Bogota2026","role":"ADMIN", ...}   ← password filtrado en la respuesta

# 3) re-lectura en OTRA request → la escritura PERSISTIÓ en la BD:
curl -s "http://localhost:8080/api/drivers/search?q=1015998877"
# → phone=+57 9999999999 | role=ADMIN | email=pwned@evil.com
#   ↑ los 3 campos prohibidos quedaron modificados y guardados (integridad de datos)
```

### Evidencia adicional del pipeline (doble fuente)

- **SAST (Semgrep):** custom rule `fleetsec-missing-authz-on-pathvariable-endpoint` (WARNING) en `DriverController.java:82` (`@PatchMapping` con `@PathVariable` sin `@PreAuthorize`).

## Impact

- **Integridad (Alta):** un atacante modifica datos de cualquier conductor (roles, PII, credenciales).
- **Confidencialidad (Baja):** fuga de password en la respuesta.
- **Interacción:** la escalada `role=ADMIN` es inocua HOY (nada enforcea el rol — V-11), pero se activa como escalada de privilegios al remediar V-11. La modificación de datos (I:H) es real e independiente del enforcement.
- **Ley 1581:** alteración no autorizada de datos personales de conductores.

## Remediation

Vincular solo campos permitidos vía un **DTO explícito** (allowlist), nunca la entidad:

```java
public record DriverPatchDto(String phone, String email) {}   // solo campos editables
// aplicar manualmente phone/email; NUNCA role/password desde el body
```

- Excluir `password`/`role` de la serialización de salida (`@JsonIgnore`).
- Verificar ownership (`#id == principal.id`) — cierra también V-09.

**Test dual (implementado · commit `49c2153`):**
1. **Rechazo:** `EnforcementRemediationTest.v05_roleAndPasswordNotAssignable` — PATCH con `role`/`password` NO los cambia (allowlist); la respuesta no incluye `password`.
2. **Flujo legítimo OK:** el mismo test valida que `phone` sí se actualiza.
3. **Interacción:** `interaction_driverCannotSelfPromoteToAdmin` — un driver autenticado NO puede escalar a admin vía V-05 (cierra la 2ª vía al takeover).
