# B-02 · CORS misconfiguration — **NO APLICA** (verificado)

| Campo | Valor |
|---|---|
| **ID** | B-02 _(candidato bonus — FSEC-19)_ |
| **Título** | Configuración CORS permisiva (`Access-Control-Allow-Origin: *` + credenciales) |
| **CWE candidato** | [CWE-942](https://cwe.mitre.org/data/definitions/942.html) · Permissive Cross-domain Policy with Untrusted Domains |
| **Estado** | ⚪ **No aplica** — verificado, la app **no habilita CORS** |

---

## Verificación

Se evaluó si la aplicación expone una política CORS permisiva (origen comodín, o reflejo del
`Origin` con `Allow-Credentials: true`), que sería el patrón vulnerable de CWE-942. **No aplica:**

```bash
# 1) Sin configuración CORS en SecurityConfig ni en ningún controller
grep -rniE "cors|@CrossOrigin|CorsConfiguration|allowedOrigins|setAllowCredentials" app/src/main/java/
#   → (sin resultados)
```

- `SecurityConfig` **no** invoca `.cors(...)` → Spring Security no registra el `CorsFilter`.
- Ningún controller usa `@CrossOrigin`.
- Sin `CorsConfigurationSource` bean.

Por defecto, Spring **no emite** headers `Access-Control-Allow-*`. Una petición cross-origin del
navegador es bloqueada por la Same-Origin Policy, no relajada por la app. No hay superficie de
CWE-942 que documentar.
